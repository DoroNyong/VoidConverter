# Void Converter – 현재 기획 정리 (초안)

> **상태: 초안.** 1:1 피드백에서 "문서 없이 게임을 만들고 있다"는 지적을 받아, 1주차 문서(노션 "Void Converter – 1주차 과제")를 **지금 게임 기준으로 다시 쓴 문서**다.
> 기준 시점: 2026-11-09, 마지막 커밋 `df8d656`. 배포된 빌드는 v0.1.4이고, 그 뒤에 만든 것은 **(개발 중)** 으로 표시했다.
> 직접 플레이로 확인하지 못한 것은 **(확인 전)** 으로 표시했다. 숫자는 `GameConfig`(설정 파일)에서 읽은 현재 값이다.

## 0. 먼저 읽는 요약

- 1주차 문서는 **"몬스터를 전부 덮어 처치하고 보이드를 밟는 합산 전투"** 게임이었다. 지금은 **"블록을 놓으면 덮은 칸 중 한 칸만 무작위로 터지는, 확률을 설계하는 게임"** 이다.
- 바뀐 이유: v0.2를 직접 해 보니 "총체적으로 재미가 없다. 기획 실수 같다"였다(몬스터가 장애물이라 모험할 이유가 없고, 보이드가 복잡). 그래서 핵심 규칙을 새로 짰다. 자세한 근거는 [playtest-v0.2.md](playtest-v0.2.md), [ideas.md](ideas.md) 아이디어 12~19.
- 그래서 1주차 문서의 칸 종류, 전투, 한 판 규칙, 몬스터, 손패 설명은 **지금 게임과 맞지 않는다.** 이 문서가 그것을 대체한다. 달라진 점의 비교표는 5절에 있다.
- 첫 피드백("직관적으로 이해가 되지 않는다")에 대한 대응으로, 1절에 **처음 보는 사람을 위한 규칙 설명과 한 턴 예시**를 따로 두었다.

## 1. 게임 규칙 한눈에

### 1.1 한 문장
5x5 판 위에 블록 하나를 놓으면, 블록이 덮은 칸 가운데 **한 칸만 무작위로 터진다.** 플레이어는 "어디에 놓아야 좋은 칸이 터질 확률이 높은가"를 고르고, 확률은 놓기 전에 화면에 보인다. 체력 6으로 전투 6번과 보스를 넘기면 이긴다.

### 1.2 칸의 종류
| 칸 | 화면 표시 | 터지면 |
|---|---|---|
| 몬스터 (물리) | 빨강, `A3` | 내 **공격력**이 숫자 이상이면 이긴다 → 숫자만큼 골드. 아니면 (숫자 - 공격력)만큼 체력을 잃는다 |
| 몬스터 (마법) | 파랑, `M1` | 내 **마법**이 숫자 이상이면 이긴다. 규칙은 물리와 같다 |
| 골드 | 노랑, `$2` | 골드 2를 받는다 |
| 회복 | 초록, `+1 HP` | 체력 1 회복 |
| 함정 | 주황, `-1` | 체력 1을 잃는다 |

- 모든 칸의 값은 처음부터 공개한다. 숨겨진 칸은 없다. (보이드 칸은 지금 끈 상태, 4.2절 참고)
- 처음 능력치: 체력 6, 공격력 2, 마법 1. 대결에는 굴림이 없다(숫자끼리 비교). 그래서 **이길지는 미리 알 수 있고, 불확실한 것은 "어느 칸이 터지느냐"뿐이다.**

### 1.3 한 번의 배치 (코어 루프)
1. **블록을 받는다.** 손패에 블록 1개가 있다(2/3/4칸 중 무작위). 마음에 안 들면 **리롤**(라운드당 2번, E 키)로 새로 받는다. R 키나 우클릭으로 돌린다.
2. **끌어서 판 위에 놓을 자리를 본다.** 끄는 동안 옆 패널에 확률이 뜬다. 예: "몬스터 50% (3마리 중 2마리 이김) / 골드 25% / 함정 25%". 블록은 놓을 수 있는 자리에만 붙는다(스냅).
3. **놓는다.** 덮은 칸 중 **한 칸만** 무작위로 터지고 결과가 적용된다(효과음과 화면 효과).
4. **덮은 칸은 전부 죽는다.** 터진 칸도, 안 터진 칸도 어두워지고 빨간 테두리가 생겨 **다시 블록을 놓을 수 없다.** 그래서 "좋은 칸을 안 터뜨리고 낭비하는" 일이 손해다.

### 1.4 한 판 (전투 한 번)
- 새 5x5 판이 만들어진다: 함정 4~5, 골드 3~4, 회복 2~3, 나머지는 전부 몬스터(13~16칸). 같은 종류가 너무 뭉치지 않게 섞는다.
- 블록을 **최소 4번** 놓아야 판을 나갈 수 있다(Leave). 최대 7번까지 놓을 수 있고, 더 놓으면 골드를 더 벌 수 있지만 체력이 깎일 위험이 커진다.
- 판을 나가면 다음 단계로 간다. 체력, 골드, 아이템은 이어진다.
- 체력이 0이 되면 패배, 다시 시작한다.

### 1.5 한 턴 예시
> 판에 몬스터 `A3`, 몬스터 `M1`, 골드 `$2`, 함정 `-1` 네 칸이 이어져 있고, 내 능력치는 공격력 2, 마법 1, 체력 6이다. 4칸짜리 블록으로 이 네 칸을 모두 덮으면 확률 패널에 이렇게 뜬다.
> - 몬스터 50% (2마리 중 1마리 이김)  ← `M1`은 이기고(마법 1 ≥ 1), `A3`은 진다(공격력 2 < 3)
> - 골드 25%, 함정 25%
>
> 놓으면 네 칸 중 하나만 터진다. `M1`이 터지면 골드 1, `A3`이 터지면 체력 1을 잃고(3 - 2), `$2`가 터지면 골드 2, 함정이 터지면 체력 1을 잃는다. 터지지 않은 세 칸은 죽어서 다시 쓸 수 없다.
> 더 안전하게 하려면 `A3`을 빼고 `M1`, `$2`만 덮는 작은 블록을 고르면 된다. 이게 "확률 설계"다.

### 1.6 한 판의 흐름 (런)
전투 → 전투 → 이벤트 → 전투 → 전투 → 이벤트 → 전투 → 전투 → 이벤트 → 상점 → 보스 (11단계) **(개발 중)**
- **이벤트**: 선택지 중 하나를 고른다(능력치 올리기, 확률 바꾸기, 아이템 얻기 등). 3.2절 목록 참고.
- **상점**: 번 골드로 아이템이나 회복을 산다. 런에 한 번, 보스 직전.
- **보스**: 전투와 같은 판에 강한 몬스터(공격력 5)가 3마리 섞여 있고, 블록을 6번 놓으면 처치할 수 있다. 보스 패턴은 아직 없다(임시 규칙).
- 보스를 처치하면 클리어다. 클리어 뒤에는 게임을 끝내거나 처음부터 다시 하게 한다(아직 결정 전).

## 3. 현재 콘텐츠

### 3.1 몬스터 (1루프 구성) **(개발 중)**
| 몬스터 | 종류·수치 | 나오는 단계 | 비고 |
|---|---|---|---|
| Slime | 마법 1 | 1단계부터 | |
| Beast | 물리 3 | 1단계부터 | 시작 공격력 2로는 지고 체력 1을 잃는다 |
| Wisp | 마법 2 | 4단계부터 | 판당 1~2마리. 이웃한 몬스터 한 마리의 숫자를 +1 올린다. 위습이 터지거나 덮이면 버프가 사라지고, 목표가 덮이면 다른 이웃을 다시 고른다 |
| Brute | 물리 4 | 7단계부터 | 판당 3마리 |
| 보스용 | 물리 5 | 보스 단계 | 3마리 섞임 |

단계 번호는 이벤트·상점까지 센 전체 번호다(전투는 1, 2, 4, 5, 7, 8단계, 보스는 11단계). 위습과 브루트는 잡기 어려워서 한 판에 나오는 수를 제한했다.

### 3.2 이벤트 (7개) **(개발 중)**
| 이벤트 | 선택지 |
|---|---|
| Lucky Shrine | 회복 칸 +30% / 골드 칸 +30% / 함정 칸 -30% (확률 가중치, 쌓이면 복리) |
| Whetstone & Rune Stone | 공격력 +1 / 마법 +1 / 지나가기 |
| Twin Altar | 공격력 +2·마법 -1 / 마법 +2·공격력 -1 / 떠나기 |
| Shady Peddler | 체력 -2로 골드 +8 / 골드 -5로 체력 +4 / 지나가기 |
| Wandering Trader | 골드 -12로 Life Charm 얻기 / 지나가기 |
| Old Chest | 체력 -3으로 Power Ring 얻기 / 두고 가기 |
| Cursed Altar | 아이템 1개를 잃고 최대 체력 +3 / 떠나기 (아이템이 있어야 선택 가능) |

- 칸 종류별 확률 가중치는 어떤 종류도 한 블록의 75%를 넘지 못한다. 넘는 몫은 다른 칸이 나눠 가진다.
- 이벤트는 3번 나오고, 7개 중에서 한 판 안에서는 중복 없이 뽑는다.

### 3.3 아이템과 상점
| 아이템 | 효과 | 상점 가격 |
|---|---|---|
| Power Ring | 공격력 +1 | 20 |
| Arcane Ring | 마법 +1 | 20 |
| Life Charm | 최대 체력 +2 | 15 |
| (회복) | 체력 +4 | 14 |

아이템은 지금 **수치만 올린다.** 배치나 확률을 바꾸는 아이템은 아직 없다(6절 참고).

### 3.4 화면 **(개발 중)**
- 판은 **마름모(가로로 긴 45도 회전 격자)** 로 그린다. 남는 네 귀퉁이를 UI에 쓰려는 계획이다. 블록은 놓을 수 있는 자리에 붙는다(스냅).
- 화면 글자는 영어(한글 폰트 없음). 도형과 색만 쓴다(그레이박스).

## 4. 지금 꺼 둔 것과 폐기한 것

### 4.1 폐기 (v0.3에서 규칙을 바꾸며 제외)
- **합산 전투**(덮은 몬스터 공격력을 모두 더해 한 번 굴림): 덮은 칸이 전부 확정으로 처리되어 모양 맞추기만 남았고, 두 마리 이상 묶는 게 위험해 모험할 이유가 없었다.
- **전부 처치 규칙**: 몬스터가 장애물이 되어 스트레스만 주었다.
- **공격력 범위 굴림**: 결과가 읽히지 않아서 단일 값으로 바꿨다.
- **손패 3개, 크기 보너스**: 새 규칙에서는 의미가 없어서 손패 1개 + 리롤로 바꿨다.

### 4.2 끈 것 (코드는 남아 있고 설정으로 켤 수 있음)
- **보이드 칸과 잠식**(4종): "복잡하고 재미없다"는 평가라서 껐다. 나중에 "물음표 칸" 하나로 줄여서 되돌릴지 검토한다(아이디어 16).

## 6. 핵심 재미 체크 3 (다시 평가)

| 점검 | 지금 상태 |
|---|---|
| 1. 세 단어로 말할 수 있나? | **고르고 → 덮고 → 터진다.** (블록을 고르고, 칸을 덮고, 한 칸이 터진다) |
| 2. 반드시 칸만으로 도나? | 격자, 블록, 칸 종류만으로 한 판이 돈다. "어디를 덮을까"는 확률 패널이 있어서 고민이 생긴다. 개발자 평가는 "이전보다 낫다" (v0.3 첫 플레이). 이후 수정판의 재미는 **(확인 전)** |
| 3. 보상이 다음 행동을 바꾸나? | **아직 약하다.** 아이템은 수치만 올린다. 다만 이벤트의 "칸 확률 가중치"는 다음 배치를 바꾸는 첫 요소다. 아이템이 확률이나 배치를 바꾸게 만드는 것이 다음 과제다 |

### 7.2 지금 보이는 문제
1. **규칙이 처음 보는 사람에게 설명되지 않는다.** 화면에 영어 숫자만 있고 튜토리얼이 없다. "왜 한 칸만 터지는가"가 화면에서 안 보인다. (이 문서 1절이 설명의 초안)
2. **아이템이 단조롭다.** 수치만 올라서 선택이 의미가 약하다.
3. **밸런스가 직접 플레이 전이다.** 봇 승률은 재미를 알려 주지 않는다는 걸 v0.2에서 확인했다. 수치(체력 6, 위습 수, 이벤트 보상)는 직접 플레이로 맞춘다.
4. **보스가 임시다.** 패턴 없이 "6번 놓으면 처치".
5. **문서가 코드를 따라가지 못했다.** 이 문서와 앞으로의 갱신 방식으로 해결한다(8절).
